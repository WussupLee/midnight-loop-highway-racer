Final local validation: full build passed with 124 unit tests and 8 Chromium browser suites. All 64 catalog/angle/viewport samples passed: minimum median contrast 2.20, minimum median relative luminance 0.075, maximum clipped-body fraction 0.64%, and projected widths spanning 26–75% of the preview opening. Thumb and tilt layouts passed on 320×568, 390×844, 844×390 and 820×1180. Local validation used Windows Chromium; the updated CI workflow is configured but has not been run remotely in this task.

## Handling decisions

[Avalanche's GDC talk on Just Cause 4](https://www.gdcvault.com/play/1026035/Vehicle-Physics-and-Tire-Dynamics) describes balancing tire-model believability with player-friendly behavior instead of assuming a more complex tire formula produces a better arcade vehicle. [Vicarious Visions' vehicle-physics presentation](https://media.gdcvault.com/gdc2016/Presentations/Donnelly_Patrick_Supercharged%20Vehicle%20Physics.pdf) emphasizes independently tunable simple systems, designer-facing parameters and stable simulation substeps. These support the tuning approach; neither source supplies Midnight Loop's coefficients. The full Avalanche slide download was unavailable, so no detailed implementation claim is attributed to it.

Local diagnosis: ordinary steering used a roughly 3.3–3.8/s input response, allowing short taps to expire before enough wheel angle developed. Handbrake grip loss approached its target in about 0.1 seconds and immediately demanded full handbrake longitudinal force. This combination made small lane corrections sluggish while drift initiation felt abrupt.

Changes are limited to steering buildup and handbrake engagement. Ordinary steering rises about 30% faster while existing maximum steering angles, speed-dependent yaw limits, drivetrain and countersteer assists remain. Handbrake grip loss uses a 0.22-second time constant and brake force follows the same progressive engagement. Exponential filtering removes the filter's timestep dependence. Existing 120 Hz force integration remains.

Measured comparison: 150 ms of 70% steer, 60% throttle, observed after 0.5 seconds, initially aligned at each speed. These are reproducible simulation measurements, not subjective playtest scores.

| Speed | Previous lateral travel | Revised travel | Change |
| --- | --- | --- | --- |
| 60 mph | 0.605 m | 0.692 m | +14.2% |
| 100 mph | 0.576 m | 0.657 m | +14.0% |
| 140 mph | 0.469 m | 0.537 m | +14.4% |

At 140 mph, a 0.5-second held handbrake at the same steering demand reduces final yaw rate from 0.649 to 0.482 rad/s (25.8%), retaining deliberate rotation. A 100 ms handbrake touch leaves a 0.188 drift blend after 0.5 seconds instead of 0.331. Tests bound tap travel to a modest 10–22% improvement, preserve left/right symmetry, verify deliberate slides, and retain the prior slalom, braking, acceleration and reversal tests.

## Showroom changes

The showroom measures solid geometry including imported root scale, fits its complete rotation envelope into the live UI opening, and uses a 30–45% camera-distance pullback as a minimum. Warm/cool local softboxes, reflected fill on temporary preview materials, and a smooth highlight shoulder before dithering make the body readable without flooding the freeway. The original driving materials and night-camera response return when the run starts. Short landscape layouts give the preview more room; the same fit code handles future vehicle sizes.

## Build verification

`npm run build` runs TypeScript, all unit tests, the production bundler, and Chromium visual tests against that production build. Install the browser once with `npx playwright install chromium`; CI installs it automatically with its OS dependencies. `npm run test:visual` reruns checks against the latest `dist`.

The visual suite discovers the live catalog instead of maintaining a separate two-car list. Each car is rendered at eight angles on desktop, portrait phone, small phone and landscape phone. A separately rendered solid-body mask excludes additive glow cards; foreground and car-hidden background frames share the same camera and postprocessing. Tests require a visible body, an eight-pixel margin inside the actual preview UI opening, bounded projected width, median contrast over 1.45, median relative luminance over 0.055, a majority of distinguishable body pixels, and fewer than 20% clipped highlights. These are art-direction regression limits, not WCAG text thresholds. Unit tests prove that dark cars with bright headlights, clipped/oversized vehicles, tiny vehicles and blown highlights fail the measurement logic. Geometry tests cover future differently sized models through a complete rotation.

The HTML report contains per-angle render evidence and measurements. Mobile tests check touch target sizes, nonoverlapping HUD/control groups, simultaneous steering/throttle, cancellation, pause/resume, audio access and hidden keyboard hints. Desktop Chromium emulation does not replace physical iPhone/Safari testing or the user's final judgment of driving feel.
